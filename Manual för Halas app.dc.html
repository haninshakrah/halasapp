Halas vård och omsorgsapp

Så ändrar du appen och tar den i bruk. Adress: haninshakrah.github.io/halasapp · Repo: github.com/haninshakrah/halasapp

0. Börja från noll: ny repo i 5 steg

Du behöver mappen github-upload (ladda ner den från Claude och packa upp den). Den innehåller allt utom arbetsflödesfilen, som du skapar direkt på GitHub i steg 3.

Steg 1. Skapa repon
  1. Gå till github.com, tryck + uppe till höger och välj New repository.
  2. Namn: halasapp. Välj Public. Kryssa i Add a README file så att repon inte är tom. Tryck Create repository.
Steg 2. Ladda upp filerna
  1. I repon, tryck Add file och Upload files.
  2. Öppna mappen github-upload på din dator. Markera allt som ligger inuti den (index.html, menu.json, support.js, ios-frame.jsx, _ds, uploads, scripts). Dra det hela in i webbläsaren. Dra inte själva mappen github-upload.
  3. Använd Chrome eller Edge, de kan ta emot mappar. Vänta tills alla filer är uppladdade (de är ungefär 30 stycken).
  4. Tryck Commit changes längst ned.
  5. Kontrollera: startsidan ska visa index.html, menu.json och mapparna _ds, scripts och uploads direkt, utan någon mapp som heter github-upload eller Family care coordination app. Är det fel, radera repon och börja om.
Steg 3. Skapa arbetsflödet (för menyn)

Dolda mappar som .github följer ofta inte med vid uppladdning, så den här filen skapas på GitHub.

  1. Tryck Add file och Create new file.
  2. Skriv i namnfältet exakt: .github/workflows/update-menu.yml (snedstrecken skapar mapparna).
  3. Klistra in texten nedan, tryck Commit changes och sedan Commit changes igen.
name: Uppdatera matsedel
on:
  schedule:
    - cron: '0 5 * * 1,4'
  workflow_dispatch:
permissions:
  contents: write
jobs:
  update:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20 }
      - run: node scripts/update-menu.mjs menu.json
      - name: Spara om något ändrats
        run: |
          git config user.name "menu-bot"
          git config user.email "menu-bot@users.noreply.github.com"
          git add menu.json
          git diff --cached --quiet || (git commit -m "Uppdaterad matsedel" && git push)
Steg 4. Slå på webbplatsen
  1. Settings, sedan Pages i vänstermenyn.
  2. Under Build and deployment: välj Deploy from a branch, branch main, mapp / (root). Tryck Save.
  3. Efter 1–2 minuter visas adressen högst upp: https://haninshakrah.github.io/halasapp/. Öppna den.
Steg 5. Ge arbetsflödet skrivrätt och kör det
  1. Settings, Actions, General. Under Workflow permissions välj Read and write permissions och tryck Save.
  2. Gå till fliken Actions. Tryck på den gröna knappen om GitHub frågar om att slå på arbetsflöden.
  3. Välj Uppdatera matsedel, Run workflow, Run workflow. Grön bock efter en stund betyder att det fungerar.

Om sidan inte syns: kontrollera att Pages-körningen under Actions är grön, att index.html ligger i roten och ladda om med Ctrl+Skift+R.

2. Små ändringar själv

Gäller text, namn, kategorier och tider.

  1. Öppna repon på github.com och klicka på index.html.
  2. Klicka på pennan (Edit this file) uppe till höger.
  3. Klicka i texten och tryck Ctrl+F (Cmd+F på Mac). Sök på det du vill ändra.
  4. Ändra texten. Rör inte tecken som {{ }}, < > eller citattecken runt orden.
  5. Tryck Commit changes, skriv en kort beskrivning och tryck Commit changes igen.
  6. Vänta ungefär en minut. Ladda om sidan med Ctrl+Skift+R (Cmd+Skift+R).
Sökord för vanliga ändringar
ROUTINE =Dagsrutinen: tid, namn och del av dagen (Morgon, Eftermiddag, Kväll). En rad per punkt. GOALS =Veckomålen: namn, antal gånger per vecka (target) och stjärnor per gång (stars). REWARDS =Belöningarna: namn och kostnad i stjärnor (cost). FAMILY =Familjemedlemmarnas namn i 4c. CATS =Kategorierna (Inköp, Hämta medicin, Övrigt med flera). Varje rad har id, namn och exempeltext. TOS =Mottagarknapparna: Sjuksköterska, Kontaktperson, Annan. 12000Hur ofta skärmsläckaren byter sida, i millisekunder. 12000 är 12 sekunder, 20000 är 20 sekunder. FosieborgsBoendets namn. seedEntriesExempelposterna. Radera raderna för att starta med en tom lista.

Gick något fel: öppna filen, välj History och sedan en äldre version. Tryck ⋯ och Revert eller kopiera tillbaka innehållet.

3. Större ändringar med Claude

Gäller nya skärmar, ny layout, nya funktioner eller flera ändringar samtidigt.

  1. Öppna projektet Family care coordination app i Claude.
  2. Skriv vad du vill ha ändrat, helst en sak i taget. Exempel: "Lägg till kategorin Frisör" eller "Gör texten på skärmsläckaren större".
  3. Granska resultatet i förhandsvisningen. Säg till om något ska justeras.
  4. Be Claude: "Skapa en ny index.html av senaste versionen". Ladda ner filen.
  5. Ersätt filen i repon: öppna repon, välj Add file, Upload files, dra in den nya index.html i roten och tryck Commit changes. Den gamla filen ersätts.
  6. Vänta en minut och ladda om sidan utan cache.

Gör inte ändringar både på GitHub och i Claude samtidigt. Då skriver den nya filen över dina ändringar på GitHub. Lägg i så fall in ändringen i Claude, eller be Claude om den på nytt.

4. Bilder

  1. Öppna mappen uploads i repon. Välj Add file, Upload files, dra in bilderna och tryck Commit changes.
  2. Bilderna visas först när de finns i bildlistan i index.html. Be Claude lägga in dem, eller sök på uploads/ och kopiera en befintlig rad.
  3. Använd bilder under 500 kB och undvik å, ä och ö i filnamnen.

Repon är publik. Lägg inte upp privata eller känsliga bilder.

4b. Bilder från ett delat Google-album

  1. I Google Foton (appen): välj Delning, Skapa delat album och ge det ett namn, till exempel "Hala".
  2. Bjud in familjen. Alla som är med kan lägga till bilder direkt från sin telefon.
  3. Albumets länk: {{ albumLabel }}
Läge: manuell synk (fungerar nu)
  1. Öppna det delade albumet på en dator. Välj ⋯ och Ladda ned alla. Du får en zip-fil.
  2. Packa upp, ändra filnamn till enkla namn utan å, ä, ö, och ladda upp bilderna i mappen uploads på GitHub (avsnitt 4).
  3. Be Claude lägga in de nya bilderna i albumlistan.
  4. Gör om det när det kommit många nya bilder, till exempel varje månad.
Läge: automatisk synk (kräver en server)
  • Det går inte att få en app att följa ett delat Google Foton-album av sig själv. Sedan 31 mars 2025 får appar bara läsa bilder de själva laddat upp. Det gäller också en server, inte bara webbläsaren.
  • Det som finns kvar hos Google är Picker-tjänsten. Då väljer en person bilder i Google Foton och appen får kopior av dem. Nya bilder i albumet följs inte, utan måste väljas om.
  • Alternativ som går att automatisera: låt familjen ladda upp bilder direkt i Halas app (kräver en gemensam databas med bildlagring), eller använd en delad mapp i en tjänst som tillåter åtkomst via länk.
  • Tills dess, använd manuell synk (ändra reglaget i Tweaks).

Albumet är synligt för alla som har länken. Lägg inte in privata bilder.

4c. Delade bilder: uppladdning direkt i appen

Bilder som familjen laddar upp i appen sparas hos Supabase, en gratis tjänst för bildlagring, och visas på surfplattan inom fem minuter. Ingen manuell synk behövs. Uppladdningen är inte provad ännu, så testa med en bild först.

  1. Skapa ett gratis konto på supabase.com och ett nytt projekt.
  2. Välj Storage, New bucket. Namn: hala-bilder. Slå på Public bucket.
  3. Välj SQL Editor, klistra in texten nedan och tryck Run. Den tillåter att bilder läses och laddas upp med nyckeln.
  4. Under Project Settings, API: kopiera Project URL och nyckeln anon public.
  5. Klistra in dem i Tweaks, i gruppen Delade bilder: supabaseUrl och supabaseKey. För att de ska gälla på alla enheter måste de stå i filen. Sök på supabaseUrl i index.html, eller be Claude lägga in dem.
  6. Familjen öppnar appens adress på sin telefon, väljer Skärmsläckare och inställningar, väljer album och trycker på uppladdning.
create policy "bilder läsa" on storage.objects for select to anon using (bucket_id = 'hala-bilder');
create policy "bilder ladda upp" on storage.objects for insert to anon with check (bucket_id = 'hala-bilder');

Obs: Nyckeln syns i sidans kod, och alla som har appens adress kan ladda upp och se bilder. Lägg inte upp privata bilder. Bilder som lagts upp i appen kan inte tas bort från appen. Radera dem i Supabase under Storage.

4d. Google Kalender: läsa, ändra och lägga in

Med en API-nyckel läser appen alla tider, även återkommande. Med ett OAuth-klient-ID kan personalen lägga in, ändra och ta bort tider i Google Kalender från appen. Båda skapas gratis i Google Cloud. Stegen är skrivna efter hur Googles konsol ser ut, men menynamnen kan ha ändrats. Prova på GitHub-adressen, inte i Claudes förhandsvisning.

A. Förbered kalendern
  1. Öppna Google Kalender, kalenderns Inställningar, Åtkomstbehörigheter för händelser.
  2. Kryssa i Gör tillgänglig för allmänheten och välj Visa alla händelseuppgifter. Annars syns inga titlar.
  3. Under Dela med specifika personer: lägg till varje person som ska ändra, med behörigheten Gör ändringar i händelser.
B. Skapa projekt och slå på kalender-API:t
  1. Gå till console.cloud.google.com och logga in med ditt Google-konto.
  2. Uppe till vänster: välj projektlistan och Nytt projekt. Namn: "Halas app". Skapa.
  3. Meny, APIs och tjänster, Bibliotek. Sök på "Google Calendar API", öppna den och tryck Aktivera.
C. API-nyckel (läsa, även återkommande tider)
  1. APIs och tjänster, Uppgifter (Credentials), Skapa uppgifter, API-nyckel. Kopiera nyckeln.
  2. Tryck Begränsa nyckel. Under Programbegränsningar: Webbplatser (HTTP-hänvisningsadresser). Lägg till https://haninshakrah.github.io/*.
  3. Under API-begränsningar: Begränsa nyckel och välj bara Google Calendar API. Spara.
  4. Begränsningen gör att nyckeln inte går att använda från andra webbplatser, så den kan stå i sidans kod.
D. OAuth-klient-ID (lägga in, ändra, ta bort)
  1. APIs och tjänster, OAuth-godkännandeskärm (kan heta Google Auth Platform). Välj Extern, ange appnamn "Halas app" och din e-postadress.
  2. Lägg till omfånget .../auth/calendar.events om du får frågan.
  3. Låt publiceringsstatus vara Testning och lägg till de Google-konton som ska ändra (du, brödrerna, personalens konton) som Testanvändare. Max 100.
  4. Uppgifter, Skapa uppgifter, OAuth-klient-ID, typ Webbapplikation.
  5. Under Behöriga JavaScript-ursprung: https://haninshakrah.github.io (utan snedstreck på slutet och utan /halasapp).
  6. Skapa och kopiera klient-ID:t. Det slutar på .apps.googleusercontent.com. Det är inte hemligt. Kopiera inte någon "klienthemlighet".
E. Lägg in dem i appen
  1. Skicka API-nyckeln och klient-ID:t till Claude, så läggs de in i index.html. Eller sök på googleApiKey och googleClientId i filen.
  2. Öppna appen på GitHub-adressen. Första gången en person ändrar något öppnas Googles inloggning. Välj kontot. Googles varning "appen är inte verifierad" är normal i testläget. Välj Avancerat och Fortsätt.
Så används det
  • Lägga in: I personalvyn, kategori Tid eller besök eller Praktiskt, med datum och tid. Posten hamnar också i Google Kalender.
  • Ändra eller ta bort: Under Kommande i Google Kalender i personalvyn. Ändra fyller i formuläret, ändra och tryck Spara. Ta bort kräver två tryck. Namnfältet måste vara ifyllt.
  • Återkommande tider: De visas som enskilda tillfällen. Att ändra eller ta bort gäller bara det tillfället. För att ändra hela serien öppnar du Google Kalender.
  • I Google Kalender: Alla ändringar där syns i appen inom 15 minuter.

5. Lunchmenyn

  • Menyn hämtas varje måndag och torsdag. Appen läser menu.json varje timme.
  • Kör den direkt: Actions, Uppdatera matsedel, Run workflow, Run workflow.
  • Rött kryss: öppna körningen och läs felet. "Hittade ingen meny" betyder att Malmö stad ändrat sin sida. Skicka felet till Claude.
  • Står det "Permission denied": Settings, Actions, General, Workflow permissions, välj Read and write permissions och spara.
  • Menyn är en vecka bakom när Malmö stad publicerar sent. Då syns den gamla menyn.

6. Ta appen i bruk

Surfplattan på väggen
  1. Öppna adressen i surfplattans webbläsare.
  2. iPad: välj Dela, Lägg till på hemskärmen och öppna därifrån, så försvinner adressfältet. Android: välj Installera app eller Lägg till på startskärmen.
  3. Slå av skärmlåset: Inställningar, Skärm, Automatisk låsning på Aldrig. Sätt surfplattan på laddning.
  4. iPad: slå på Guidad åtkomst (Tillgänglighet) så att ingen kan lämna sidan av misstag. Android: använd en kioskapp, till exempel Fully Kiosk Browser.
  5. Sidan visar tid och datum själv. Den byter sida var 12:e sekund och behöver inga tryck.
Personalen
  • Samma adress, vyn "Personal" (4b). Skriv namn, välj kategori och mottagare, och spara.
  • Den som tar emot trycker Kvittera. Namn, dag och tid loggas på posten.
  • Poster med datum i Tid eller besök och Praktiskt visas på skärmsläckaren.
Familjen
  • Samma adress, vyn "Familj" (4c). Välj namn, kategori och mottagare.
  • Familjen ser om personalen kvitterat och trycker själv "Kvittera läst".
  • Kalendern är Halas Google-kalender. Alla med länken kan lägga in tider.

6b. Skärmsläckarens sidor, dagsrutin, mål och stjärnor

Skärmsläckaren
  • Fasta delar: veckodag, datum, klocka, veckonummer, och en grön rad med Just nu och Härnäst.
  • Sidor som byter var 12:e sekund: Idag, Dagsrutin, Mina stjärnor, Den här veckan, Veckans matsedel, och Hälsningar från familjen när sådana finns.
  • Just nu och Härnäst räknas från dagsrutinen och dagens aktiviteter.
  • Appen försöker även läsa Halas Google-kalender. Webbläsare blockerar ofta det. Fungerar det inte, lägg in tiderna som poster i personalvyn.
Dagsrutin (personalen)
  1. Skriv ditt namn i namnfältet i personalvyn (4b).
  2. I rutan Dagsrutin idag trycker du på en punkt när den är gjord. Den får en bock och visas överstruken på skärmsläckaren.
  3. Håll musen över punkten för att se vem som bockade av och när.
  4. Bockarna nollställs varje natt. Tryck igen för att ångra.
Mål och stjärnor (personalen)
  1. Skriv ditt namn i namnfältet.
  2. Tryck på ett mål i rutan Mål och stjärnor när Hala har gjort det, till exempel träning eller promenad. Hon får stjärnor enligt målet och namn och tid loggas.
  3. När veckans antal är nått blir knappen grön. Fler tryck ger inga extra stjärnor.
  4. Gick det fel, tryck Ångra senaste.
  5. När saldot räcker för en belöning blir knappen Lös in röd. Tryck på den när belöningen har genomförts, och skicka sedan ett meddelande till familjen i 4c eller 4b, så att de kan boka frisör eller utflykt.
  6. Målen nollställs varje måndag. Stjärnorna sparas.
Anpassa

Mål, belöningar och dagsrutin ändrar du i filen. Sök på GOALS =, REWARDS = eller ROUTINE = (avsnitt 2). Ändra bara namn och siffror, och behåll tecknen runtom. Vill du lägga till en punkt, kopiera en hel rad och ge den ett nytt id.

7. Att veta innan ni börjar använda den på riktigt

  • Poster delas inte mellan enheter. Det som personalen skriver in, bockar av i dagsrutinen eller loggar som mål och stjärnor syns bara i webbläsaren på den enhet där det gjordes. Surfplattan, personalens telefoner och familjens telefoner ser alltså olika listor. Kvittenserna och loggen gäller på samma sätt bara på den enheten.
  • Lösning: Koppla in en gemensam databas, till exempel Firebase eller Supabase. Be Claude om det. Du behöver då skapa ett gratis konto och klistra in en nyckel.
  • Ingen inloggning och inga aviseringar. Alla som har adressen kan läsa och skriva. Adressen är öppen på internet.
  • Känsliga uppgifter. Skriv inte personnummer, diagnoser eller medicinuppgifter i appen innan databas, inloggning och regler för personuppgifter finns på plats. Prata med boendet om vad som får registreras.
  • Inga albumuppladdningar från telefoner. Bilder läggs in via repon.

8. Rekommenderad ordning

  1. Skapa repon och lägg upp filerna (avsnitt 0).
  2. Kontrollera att menyflödet fungerar och att menu.json uppdateras (avsnitt 0, steg 5 och avsnitt 5).
  3. Ta bort exempelposterna (sök på seedEntries) och byt namn och bilder till era egna.
  4. Prova flödet själv: skicka som familj i 4c, kvittera som personal i 4b och kontrollera loggen.
  5. Ställ in surfplattan (avsnitt 6).
  6. Be Claude koppla in en gemensam databas, så att alla ser samma poster.
  7. Be om inloggning och aviseringar när databasen fungerar.
